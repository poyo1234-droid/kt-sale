# 仕様書｜セール価格設定リスト データ仕様

最終更新: 2026-09-04

セール価格設定リストを kintone で作るための、入力データの取得手順と各項目の出どころを
まとめたもの。ZOZO からのダウンロード操作そのもの（画面キャプチャ付き）は別の Word
マニュアルに置き、本書はデータの中身と処理仕様を扱う。

---

## 1. 全体の流れ

```
ZOZO BACK OFFICE
  ├ 売上（注文日ベース）  ─┐
  ├ 在庫分析              ─┤
  ├ 在庫（S在庫）          ─┼→ kintone 各アプリへ取り込み → セール価格設定リスト生成
  ├ セールグッズ salegoods ─┤                                    → メーカーへ送信
  └ 商品マスタ goods      ─┘
```

---

## 2. データの取得

ZOZO BACK OFFICE から以下をダウンロードする。操作画面は Word マニュアルを参照。

### 2-1. 売上（注文日ベース）

| 項目 | 内容 |
|---|---|
| 場所 | 分析 > 売上集計（`to.zozo.jp/to/Sales.asp?c=SalesSummary`） |
| 条件 | ショップ = FUNALIVE / ベース = 売上 +「日計で表示する」チェック / 注文CSV = 注文番号なし |
| 期間 | **前回セール開始日 〜 リスト作成日の月曜日** |

期間は毎週月曜にこの範囲を毎回取り直す。前回セール開始日が回ごとに変動するため、
差分ではなく毎回フルで取る。

### 2-2. 在庫分析

| 項目 | 内容 |
|---|---|
| 場所 | 分析 > 在庫分析データ（`StockAnalysis.asp?c=init`） |
| 必須設定 | **「最終入荷日」と「お気に入り登録数」の "表示する" にチェック** |
| その他 | ショップ指定なし / お気に入り登録数の期間指定はしない（＝直近30日）/ 他はデフォルト |

### 2-3. 在庫（S在庫）

| 項目 | 内容 |
|---|---|
| 場所 | 分析 > 在庫（`zaiko_csv2.asp?c=Zaiko`） |
| 条件 | 全項目デフォルトのまま（表示全店・指定なし・抽出形式 SKU毎） |

### 2-4. セールグッズ（前回のセール価格設定内容）

| 項目 | 内容 |
|---|---|
| 場所 | 商品管理 > セール設定 > セール予約確認（`SaleSettingRegist_Tenant.asp`） |
| 条件 | ラジオボタンはデフォルトのまま検索 → 一覧から CSV ダウンロード |

**絞り込みは一切できない。** 現在登録中のセールしか表示されず、セールが未登録の間は
0件でダウンロード項目自体が出ない。**次回のセールを設定すると前回分は消えるので、
消える前に取ること。**

## 6. 在庫数の仕様

### 6-1. 決定事項

**在庫数は S在庫の `在庫数`（L列）を正とする。今後はこれのみを使う。**

在庫分析の `販売可能数` / `販売可能数合計` は採用しない。
新テンプレートでも `販売可能数` の列は廃止され、在庫は1列だけになった（§9参照）。

### 6-2. 在庫分析の列の関係（全142,979行で例外ゼロ）

```
販売可能数合計 = 販売可能数 + 販売開始前点数 + 販売前予約受付数
```

この3列が食い違う行は1,959行（1.4%）。販売開始前点数>0 が1,765行、販売前予約受付数>0 が264行。

### 6-3. S在庫の在庫数と在庫分析の差 ＝ 引当（注文済み・未出荷）

両ファイルは同一スナップショット（基準日はどちらも 2026/8/3）。共通するCS品番131,710件で
`在庫数 == 販売可能数合計` は 124,372件（94.4%）、差>0 が7,100件。

差が出る行だけ直前に売れている。

| | 前日販売数>0の割合 | 直近7日 平均 | 直近30日 平均 |
|---|---|---|---|
| 差>0（7,100件） | **61.8%** | 1.70 | 4.67 |
| 一致（124,372件） | **0.1%** | 0.03 | 0.26 |

差の大きさも販売数の範囲に収まる。

```
差 == 前日販売数      : 51.7%
差 == 直近7日販売数   : 71.2%
差 <= 直近7日販売数   : 93.7%
差 <= 直近30日販売数  : 99.3%
```

**S在庫の在庫数は引当分を引いていない。在庫分析の販売可能数は引いた後。**

例外47件は直近30日販売数=0なのに差が1ある長期在庫。返品保留や不良品扱いの可能性があるが、
データからは判定できない。

### 6-4. 価格は完全一致

共通131,710件で `価格タイプ` の不一致0件、S在庫 `販売価格(税抜)` と 在庫分析 `現在価格` の
不一致0件。両ファイルでズレているのは在庫数だけ。

## 7. 対象品番の母集団と抽出条件

### 7-1. リストに載せる品番の抽出条件

**`goods.csv` のブランド品番のうち、S在庫に在庫があるものだけをリストに載せる。**

| | 件数 |
|---|---|
| goods.csv 全ブランド品番 | 53,515 |
| うち **S在庫に存在**（＝在庫がある） | **25,078** |
| 実際の送信リストのブランド品番 | 25,051 |
| 両者の一致 | **25,038（99.95%）** |

差はS在庫側に40品番、リスト側に13品番のみ。goods は廃番も含む全品番マスタで
半数以上（53.1%）は在庫がないため、この絞り込みが必要。

### 7-2. CS品番（SKU）レベルの差

リストの粒度はブランド品番単位のため、CS品番の差はブランド品番単位で見る必要がある。

CS品番は **S在庫を正とする**（132,201件）。

| | 件数 | ブランド品番単位で見ると |
|---|---|---|
| 共通 | 131,710 | — |
| S在庫のみ | 491 | ブランド品番ごと在庫分析に無いのは **83品番** |
| 在庫分析のみ | 11,269 | うち在庫あり540件。ブランド品番ごとS在庫に無いのは **13品番** |

- S在庫には **在庫数=0 の行が1件も存在しない**（在庫分析は13,290件が0）。
- 在庫分析にしか無い540件のうち **505件（93.5%）はブランド品番自体がS在庫に存在する**。
  その品番の行はリストに出るので、影響はそのSKU分の在庫数だけ。在庫をS在庫と定義した以上、
  これは正しい挙動。
- S在庫にしか無い491件のうち、ブランド品番ごと在庫分析に無いのは83品番。この83品番は
  実績列（S/U/V/W）が取れない。**→ 0埋めする（§10 決着済み）**

## 8. 直近セール実績の紐付け

新テンプレート I〜L列（旧様式 AD〜AH列）の出どころ。**結合キーはブランド品番のみ。**
メーカー・親カテ・子カテを組み合わせる必要はない。

### 8-1. セール価格・オフ率・セール前在庫数 → salegoods.csv

送信リスト25,500行のうち salegoods に品番がある18,578行（72.9%）で、**全項目100%一致**した。

| リストの項目 | salegoods.csv の列 | 一致 |
|---|---|---|
| 直近セール価格（税抜き） | `変更後セール価格` | 18,578 / 18,578（**100%**） |
| 直近セールオフ率 | `オフ率` | 18,578 / 18,578（**100%**） |
| セール前在庫数（旧AH列） | `在庫数`（ブランド品番で合計） | 18,578 / 18,578（**100%**） |

salegoods に無い6,922行のうち **6,893行は実績列が全て0または空**。紐付かないのではなく、
**前回セール対象外だから0**というだけ。§5 の「salegoods は27%欠ける」はこの対象外分にあたる。

### 8-2. 受注数・売上額 → S売上(セール成績).csv の「セール分のみ」

**`価格タイプ = セール` の行だけを集計する。プロパー分は除外する。**

| 集計方法 | AD 受注数の一致 |
|---|---|
| **`価格タイプ = セール` のみ** | **25,500 / 25,500（100.00%）** |
| 全体（プロパー込み） | 25,254 / 25,500（97.9%） |

| 項目 | 売上ファイルの列 | 一致 |
|---|---|---|
| 受注数 | `注文数`（ブランド品番で合計） | 25,500 / 25,500（**100.00%**） |
| 売上額 | `合計金額`（ブランド品番で合計） | 25,496 / 25,500（**99.98%**、不一致4行） |

売上ファイルは セール6,733行 / プロパー1,595行が混在する。プロパーを除外しないと
「AD=0なのに売上に実績がある」行が894件出る。

品番が売上ファイルに無い場合は **0** とする。

### 8-3. 期間の整合

0803データでは、売上ファイルの `注文日` が `20260801〜20260803`、salegoods の
`セール開始予定日時` は `2026/8/1 8時台` が23,472件。
**前回セール（8/1開始）の開始日から今回のリスト作成日までの売上**が入っている。
§2-1 の取得期間ルール（前回セール開始日〜リスト作成日の月曜日）と整合する。

## 9. セール価格設定リストの様式

### 9-1. 新テンプレート（2026-09-04 以降はこれ）

`260615-セール設定リスト\260904セール設定リスト改善案.xlsx` の
シート **「セール価格設定リスト (改善案)」** が今後の様式。
運用上の実体は Google スプレッドシート「セール価格設定リストテンプレート」（§9-4）。

- **45列 → 23列**に削減
- 1行目・2行目が2段ヘッダー、**データは3行目から**
- **粒度はブランド品番単位。CS品番はリストに出てこない。**

| 列 | 大見出し | 項目 | 出どころ・備考 |
|---|---|---|---|
| A | | 親カテゴリ | |
| B | | 子カテゴリ | |
| C | | ブランド品番 | **goods.csv**（§5） |
| D | | 主性別 | |
| E | 商品タイプ | (親) | |
| F | | (子) | |
| G | | 品名 | |
| H | | プロパー価格（税抜） | 旧「元上代」 |
| I | 直近セール実績 | 受注数 | salegoods |
| J | | 売上額 | salegoods |
| K | | 直近セール価格（税抜き） | salegoods |
| L | | 直近セールオフ率 | salegoods |
| M | | 直近セール価格（税込み） | **数式** |
| N | 入力項目 | オフ率から設定(↓) | **メーカー入力欄**（直近のセールをオフにしたい場合は「0」） |
| O | | 税込価格から設定(↓) | **メーカー入力欄** |
| P | セール設定価格 | オフ率 | **数式** |
| Q | | セール価格（税込み） | **数式** |
| R | | セール価格（税抜き） | **数式** |
| S | | 初回販売開始日 | 在庫分析 `初回販売開始設定日` |
| T | | **在庫** | **S在庫の `在庫数`**（§6） |
| U | 直近の販売数 | 直近30日 販売数 | 在庫分析 |
| V | | 直近7日 販売数 | 在庫分析 |
| W | | 直近30日お気に入り登録数 | 在庫分析 |

**メーカーが入力できるのは N・O の2列のみ。**

#### 計算式

```
M 直近セール価格（税込み） = IF(K3="","",ROUND(K3+K3*0.1,0))

R セール価格（税抜き）
  = ROUND( IF(NOT(N3=""), ROUND(H3-H3*ROUND(N3,3),0),
           IF(NOT(O3=""), O3/1.1,
                          H3)), 0)

Q セール価格（税込み） = IF(R3="","",ROUND(R3+R3*0.1,0))

P オフ率 = IF(OR($R3="",$H3=$R3),"",
             ROUNDDOWN(1-($Q3/ROUND(($H3*1.1),0)),3))
```

N（オフ率）が優先。N が空なら O（税込価格）。どちらも空ならプロパー価格 H のまま。
消費税率は数式に 10% がハードコードされている。

### 9-2. 旧様式からの変更点

**廃止された列**

```
ﾒｰｶｰNo. / メーカー名 / ブランド / SKU数 / 元上代（→プロパー価格（税抜）に改称）
MAX割引額 / MAX割引率 / 直近割引率 / 販売タイプ / 販売開始日
販売可能数 / 精算掛率 / 消費税率 / 開始日時 / 終了日 / セール種別
```

- **SKU数は廃止。** 出どころが特定できていなかったが、新様式では不要になった
- **販売可能数（在庫分析の販売可能数合計）は廃止。**在庫は S在庫の `在庫数` 1列のみ
- 入力欄が **3つ→2つ**。「値引き金額 入力」は廃止

**追加された列**

```
子カテゴリ / 直近セール価格（税抜き）/ 直近セールオフ率 / 直近セール価格（税込み）
セール価格（税込み）/ セール価格（税抜き）/ 直近30日お気に入り登録数
```

**改善案の 6月版 → 9月版 の差分は1箇所のみ**：19列目が `販売開始日` → `初回販売開始日`。

### 9-3. 旧様式（参考・2026-09-04 まで）

`送信\00002-株式会社 スタンレーインターナショナル様 セール価格設定リスト20260808～20260821.xlsx`
ほか206ファイル。45列。在庫が2列あり、出どころが異なっていた。

206ファイル・25,500行を全件照合した結果：

| 旧リストの列 | 照合先 | 一致率 |
|---|---|---|
| **Z列「在庫」** | **S在庫の `在庫数`** | **99.92%**（25,479/25,500） |
| Z列「在庫」 | 在庫分析の販売可能数合計 | 82.10% |
| **Y列「販売可能数」** | **在庫分析の `販売可能数合計`** | **99.72%**（25,428/25,500） |
| Y列「販売可能数」 | 在庫分析の販売可能数 | 95.02% |

旧システムは Y と Z を別の出どころから取り、2列並べてメーカーに見せていた。
両者の差がそのまま引当分にあたる（§6-3）。新様式では Z 側だけが残る。

### 9-4. テンプレートの行数とフィルタ範囲（2026-09-04 対応）

新テンプレートの実体は Google スプレッドシート **「セール価格設定リストテンプレート」**。
kintone の JS がこれを読み込み、コピーして Google ドライブに各メーカー分を出力する。

https://docs.google.com/spreadsheets/d/1B4Zv20QQbQyFauUcrfl6tf0QrrP-ah7TeV-BEHHn8rA/

#### 判明した問題

**出力ファイルのフィルタ範囲が全件 `A2:AG3` で固定されていた。**
無作為25件と1,316行の大口ファイルを調べて全件同じ。60行のファイルでも1,316行のファイルでも
**3行目までしかフィルタが効いていない**。テンプレート側のフィルタ範囲（2〜3行目）が
そのままコピーされ、データ行が追加されても広がっていなかった。

#### 実測した行数（`送信` フォルダの .xlsx／3期間・620ファイル）

| セール期間 | 件数 | 最大行 | 中央値 | 1000行超 |
|---|---|---|---|---|
| 2026/08/01〜08/07 | 206 | 1,292 | 59 | 3件 |
| 2026/08/08〜08/21 | 206 | 1,316 | 60 | 3件 |
| 2026/08/22〜09/04 | 208 | 1,267 | 61 | 3件 |

行数が突出しているのは毎回同じ3社（00096 アリエス様 / 00219 FINE様 / 00027 メンズ・サンエー様）。
他は中央値60行程度。

**出力ファイルに空行は一切ない**（行要素数＝最大行番号）。書き込み側がデータ行数ぴったりに
行を削除して揃えている。したがってテンプレートの行数を増やしても、空行が出力に残ることはない。

#### 対応

- テンプレートを **1,000行 → 2,000行** に拡張。Q列・R列の数式と書式も2,000行目まで複製
- フィルタを **`A2:W2000`** で作り直し

#### 注意：列全体（`A:W`）指定は使えない

このテンプレートは1行目がグループ見出し（結合セル）、2行目が実際の列名という2段ヘッダー。
列全体でフィルタを作ると**フィルタボタンが1行目に付いてしまい、フィルタとして機能しない**。
範囲は必ず2行目始まり（`A2:W○○`）で指定すること。

#### 未確認

- 修正後のテンプレートで1社分出力し、フィルタ範囲がデータ行数まで広がるかの実地確認
- 行削除に伴ってフィルタ範囲も縮む想定だが、書き込み側の実装は未読
  （kintone の JS も GAS も接続フォルダには存在しない）

### 9-5. メーカーごとのファイル分割

1メーカーが複数ファイルに分かれることがある。**分割するかどうか、どの単位で分けるかは
メーカーごとの個別設定**で、データからは導出できない。

#### 分割の単位（今後の運用）

**今後は「親カテゴリ単位」か「メーカー単位」の2つだけ。子カテゴリ単位は廃止する。**

旧システムは子カテゴリ単位の分割も行っていた（`51 グルービー`）。
CLAUDE.md の「分割粒度はセール返答表の指定粒度と一致させる」という運用ルールに基づく。

#### 分割設定の持ち方

**kintone のメーカーマスターに、メーカーごとの設定として持たせる。**
「メーカー単位で出力するか、親カテゴリ単位で出力するか」をメーカーマスター側で制御する。
（2026-09-04 時点でエンジニアが実装中）

旧システムでは次のメール配信ツールが設定を持っていた。移行後の参照元はメーカーマスターだが、
現行の運用実態を確認するときはこちらを見る。

#### 旧システムでの分割設定（メール配信ツール）

`T:\10_業務資料\ファンアライブ\250829サーバー更新\260723-セール返信メールリスト\
○セールメール自動送信ツール\○セールメール自動送信ツール.xlsm`
の **「作成メーカー設定」シート**が分割設定を持つ。データ行は8行目から。

| 列 | 内容 |
|---|---|
| CI | 個別添付ファイル名 |
| CN | メーカーコード |
| CO | メーカー名 |
| **CP** | **子カテ（＝分割単位。ファイル名のサフィックスになる）** |
| CQ | 送信対象（`●` のみ送る） |
| CR | ファイル有無（`1` のみ送る） |

1分割単位 = 1行。`送信対象=●` かつ `ファイル有無=1` の行だけが実際に送られる。
使われていない枠（ButterflyTwists / YUASA5 select / YUASA8 select など）も残っている。

> 列名は「子カテ」だが、実際に入るのは親カテゴリ名のこともある（`YUASA4 select` は親カテゴリ）。
> 名称に引きずられないこと。

#### 親カテゴリが複数でも分割しないメーカーがある

「親カテゴリが複数なら分割」というルールではない。実データで確認した非分割の例:

```
00002  MEI / SI select
00006  GERRY / HANES / KOD SELECT / OUTDOOR / Toucan Surfing
00025  BLACK JACKALL CROWN / Diliraba / EVER METAL / Ree＆Mee
00052  LKJ select / POWERS select
```

**分割の有無は必ずメール配信ツールの設定を見ること。**

#### サフィックス無しの全件ファイルは送らない

分割メーカーのフォルダには、分割ファイルとは別に**サフィックス無しの全件ファイル**が存在する。
行数は分割分の合計と一致する（例: 湯浅 229行 = YUASA4 141 + YUASA6 88）。

**これは中間ファイルであり、メーカーには送っていない。**
メール配信ツールに該当する行が1つも存在しないことで確認済み。
