# 仕様書：キントーン移行 — セール価格設定リストの突合

- 対象スクリプト：`検証スクリプト/キントーン突合.py`（新規）／`検証スクリプト/_共通.py`（パス定義を追記）
- 作成日：2026-09-01
- ステータス：**スクリプト実装済み。メーカー2・4 の2件で試行し、要確認事項を8件検出**
- 前提：旧システムは `sale処理-v53.xlsm`。キントーン側は kintone から出力した xlsx を Drive 経由でローカルへ DL したもの

セール価格設定リストの生成が旧システム（`sale処理-vNN.xlsm`）からキントーンへ移る。
**同じメーカーに対して両者が出したリストを突き合わせ、キントーンが旧システムを再現できているかを確認する**ためのスクリプトと、その初回実行で判明した差分をまとめる。

---

## 1. 突合の対象

| | 旧システム | キントーン |
|---|---|---|
| 出力元 | `sale処理-v53.xlsm` | kintone |
| ファイル名 | `00002-株式会社 ○○様 セール価格設定リスト20260221～20260306.xlsx` | `2_株式会社 ○○様_セール価格設定_20260207～20260220.xlsx` |
| 置き場所 | `..\260220-セール情報設定リスト202602219～202603069\送信\` | 同 `\260901kintone突合\` |
| 列数 | 45列（A:メーカーNo. 〜 AJ:精算掛率） | 23列（A:親カテゴリ 〜 W:直近30日お気に入り登録数） |
| データ開始行 | 3行目（1行目=グループ見出し / 2行目=項目名） | 同じ |
| 突合キー | E列 ブランド品番 | C列 ブランド品番 |

ファイル名の**先頭の数字をメーカーNo.** として対応付ける（旧の `00002` と キントーンの `2` は
`int()` を通して同じ `'2'` に正規化する）。

旧システムは1メーカーが子カテゴリ単位で複数ファイルに分かれることがある
（`00009-…ガレージ様 …_Garageroom.xlsx` など）。同じメーカーNo. のファイルは
1つの dict にまとめて読み、品番が重複した場合は最初のものを採り、標準出力に警告を出す。

## 2. 列マッピング

キントーン23列のうち21列が旧システムの列に対応する。スクリプトの `ATTR` / `PERF` がその定義。

### 2.1 属性項目（`ATTR`）— 基準日に依存しない

出力した日がいつであろうと同じ値になるべき項目。**不一致はどちらかの不具合を意味する。**

| 比較項目 | キントーン | 旧システム |
|---|---|---|
| 親カテゴリ | A | C 親カテゴリー |
| ブランド(子カテゴリ) | B 子カテゴリ | D ブランド |
| 主性別 | D | F |
| 商品タイプ(親) | E (親) | G (親) |
| 商品タイプ(子) | F (子) | H (子) |
| 品名 | G | I |
| プロパー価格 | H プロパー価格（税抜） | K 元上代 |
| セール価格(税抜) | R セール価格（税抜き） | R 税抜価格(設定価格) |
| セール価格(税込) | Q セール価格（税込み） | S 税込表示 |
| オフ率 | P | T |

### 2.2 実績項目（`PERF`）— 出力日のスナップショット

在庫や販売数など、出力した日によって変わる項目。**両者の基準日が違えば不一致が出るのが正常**であり、
突合の合否判定には使わない（傾向確認のため出力はする）。

| 比較項目 | キントーン | 旧システム |
|---|---|---|
| 販売開始日 | S | X |
| 在庫 | T | Z |
| 直近30日販売数 | U | AA |
| 直近7日販売数 | V | AB |
| お気に入り登録数 | W 直近30日お気に入り登録数 | AC |
| 受注数 | I | AD |
| 売上額 | J | AE |
| 直近セール価格(税抜) | K 直近セール価格（税抜き） | AF SALE価格 |
| 直近セールオフ率 | L | AG SALEオフ率 |

### 2.3 対応先が無い項目

**旧システムにあってキントーンに無い（12項目・`ONLY_KYUU`）**

`メーカーNo.(A)` / `メーカー名(B)` / `SKU数(J)` / `MAX割引額(L)` / `MAX割引率(M)` /
`直近割引率(N)` / `値引き金額 入力(P)` / `販売タイプ(V)` / `初回販売開始日(W)` /
`販売可能数(Y)` / `セール前在庫数(AH)` / `精算掛率(AJ)`

このうち **`MAX割引率` `直近割引率` `販売タイプ`（予約判定）`SKU数`** は、
セール価格設定リストの「項目説明」シートでメーカー様向けに説明されている項目であり、
メーカー様が割引率を決める材料になっている。→ 7章④

**キントーンにあって旧システムに無い（`ONLY_KINTONE`）**

`直近セール価格（税込み）(M)`

### 2.4 入力欄の対応

メーカー様が記入する欄。値の突合対象にはしない。

| | キントーン | 旧システム |
|---|---|---|
| オフ率から設定 | N | O オフ率 入力(↓)優先 |
| 税込価格から設定 | O | Q 税込価格から設定 入力(↓) |

旧システムには **P列「値引き金額 入力」** もあり、キントーンには無い（→ 2.3）。

## 3. 突合ロジック

### 3.1 値の正規化（`正規化()`）

両者は同じ内容でも型が違うことがあるため、比較前に文字列へ寄せる。

| 入力 | 出力 |
|---|---|
| `None` | `""` |
| `datetime(2026,2,7)` | `"2026/02/07"` |
| `12000.0`（float だが整数値） | `"12000"` |
| 全角空白・連続空白を含む文字列 | 半角1個に潰す |

品名には全角空白（`POPEYE　PT CREW SWEAT`）が入るため、この吸収が無いと全件が不一致になる。

### 3.2 突合（`突合()`）

ブランド品番で内部結合し、3つに分ける。

| 区分 | 意味 |
|---|---|
| 共通 | 両方にある → `ATTR` / `PERF` を項目ごとに比較 |
| キントーンのみ | 旧システムが出力対象から外している、または旧の出力後に登録された新商品 |
| 旧システムのみ | キントーンの商品マスタに無い → **移行漏れの疑い** |

## 4. 使い方

```bash
cd 検証スクリプト

# 既定のフォルダ同士を全メーカー突合
python キントーン突合.py

# メーカーNo. を指定して絞る
python キントーン突合.py --メーカー 2 4

# フォルダと出力先を明示する（回が変わったとき）
python キントーン突合.py --kintone <キントーン出力フォルダ> --旧 <送信フォルダ> --out <出力先.xlsx>
```

既定のフォルダは `_共通.py` の `KINTONE_LIST` / `KYUU_LIST`。
出力先を省略すると **キントーン側フォルダに `YYMMDD_kintone_旧システム_突合結果.xlsx`** を作る。

標準出力にはメーカーごとの件数と不一致数、最後に合計と「片方にしか無いメーカー」の一覧が出る。

```
メーカー  2 株式会社 スタンレーインターナショナル
    キントーン   830行（在庫あり 121） / 旧   140行 / 共通   138 / kのみ   692 / 旧のみ 2
    属性の不一致 28 件 / 実績の不一致 619 件（参考）
```

依存は `openpyxl` のみ。Excel は不要なので、`TXT出力を実行.py` と違い pywin32 も要らない。

## 7. 検出した要確認事項

### ① 行数の差は「在庫フィルタの有無」で説明できる

旧システムは **在庫 > 0 かつ 販売可能数 > 0** の品番だけを出力している（メーカー2の140行は全件が在庫>0、
在庫0の行は1件も無い）。対してキントーンは在庫の有無に関わらず全件出力しており、
メーカー2の830行のうち **709行が在庫なし**。

キントーンのみ692件の内訳：

| | 件数 |
|---|---|
| 在庫なし（旧システムの出力対象外） | 688 |
| 在庫あり（旧の出力後に登録された新商品） | 4 |

→ **キントーン側に在庫フィルタが未実装の可能性。**仕様として意図的なのか確認が必要。
在庫0の扱いは v53 仕様書 7.2 でも論点になっている。

### ② 親カテゴリ 28件の不一致 — 旧システム側が誤っている可能性が高い

28件すべてが `旧[SI select] → キントーン[MEI]`。ZOZO の在庫分析
（`..\260825-ZOZOデータ\在庫分析20260825.csv`）と照合すると:

| キントーンの親カテゴリ | ZOZO の親カテゴリ | 件数 |
|---|---|---|
| SI select | SI select | 98 |
| MEI | MEI | 14 |
| MEI | （ZOZO に無し＝販売終了） | 718 |

**ZOZO にデータが残る112件では、キントーンの親カテゴリが100%一致している。**
`MEI` はスタンレーインターナショナル様が実際に持つ親カテゴリであり、
**旧システムがメーカー単位で親カテゴリを固定していた疑い**がある
（不一致28件はいずれも ZOZO から消えた品番で、旧システム出力時に照合できなかったもの）。

### ③ 【旧システムの不具合】販売開始日が文字列として10文字で切り捨てられている

旧システムの X列（販売開始日）は、メーカー2で **140件中139件**、メーカー4で **83件中71件** が
`2026/2/7 8` という**10文字の文字列**になっている。本来の `2026/2/7 8:45:00` が途中で切れており、
日付型ですらない。並べ替えや期間での絞り込みが正しく動かない。

キントーン移行を機に是正すべき。**この項目は 6章の「属性一致」の判定には含めていない**
（`PERF` に分類されているため）が、基準日相違では説明できない不一致である。

### ④ 【キントーンの不具合】販売開始日が大半空欄／残りも同一日付

キントーンの S列（販売開始日）は **メーカー2で830件中663件、メーカー4で319件中256件が空欄**。
値が入っている分もすべて `2026/08/22` の1種類のみで、商品ごとの実際の販売開始日が入っていない。
出力ロジックの確認が必要。

### ⑤ 旧システムにあってキントーンに無い項目が12個

2.3 のとおり。とくに **`MAX割引率` `直近割引率` `販売タイプ` `SKU数`** は
「項目説明」シートに説明があり、メーカー様が割引率を決める材料になっている。出力要否の確認が必要。

### ⑥ 旧システムのみ2件（メーカー2）

| ブランド品番 | 品名 | 元上代 | 在庫(2/20) | SKU数 |
|---|---|---|---|---|
| CAS-000-231002 | California Sportswear JNGL FATIGUE… | 16,000 | 5 | 6 |
| CAS-000-231003 | California Sportswear UTILITY TR… | 12,000 | 1 | 3 |

2月時点では在庫があった品番がキントーンの商品マスタに無い。**廃番による削除か移行漏れか**の確認が必要。

### ⑦ 出力基準日が違うため実績値は今回の突合対象外

旧システム＝2026/02/20、キントーン＝2026/09/01 のスナップショット。
在庫・販売数・お気に入り数・セール実績の不一致（メーカー2で619件、メーカー4で544件）は
**すべてこの差で説明がつく**ため、`4_値違い_実績(参考)` に分離している。

**実績項目まで検証するには、キントーン側で 2026/02/20 基準のデータを再出力する必要がある。**

### ⑧ ファイル名の期間表記が両者でずれている

| | 期間表記 |
|---|---|
| 旧システム | `20260221～20260306`（**セール実施期間**） |
| キントーン | `20260207～20260220`（**前回セール期間**と思われる） |

同じ回のリストを指しているのに表記の意味が違う。メーカー様が受け取ったときに混乱するため、
**どちらの期間を書くのかを統一**すべき。突合スクリプトは期間表記を見ずにメーカーNo. で対応付けているため、
この差は突合の妨げにはならない。

## 9. スクリプトを他の回に流用するとき

`_共通.py` の `KINTONE_LIST` / `KYUU_LIST` が既定値だが、回ごとにフォルダが変わるので
**`--kintone` / `--旧` で渡すほうが確実**。`_共通.py` の書き換えは、その回を既定にしたいときだけ行う。

キントーン側の列構成が変わった場合は、`キントーン突合.py` 冒頭の
`ATTR` / `PERF` / `ONLY_KYUU` / `ONLY_KINTONE` / `KINTONE_NAME` を直す。
列番号は**1始まり**（A=1）。`KINTONE_NCOL` / `KYUU_NCOL`（読み込む列数）と
`KINTONE_STOCK`（在庫列＝在庫ありの判定に使う）も列構成に連動する。
