# 検証スクリプト

ブックが出力する TXT（ZOZO アップロード用）を、担当者の本番出力と突き合わせるためのもの。
2026-08-04 に v53 の検証で使用し、**51ファイル・1,087,129文字が1文字も違わない**ことを確認した
（`仕様書/仕様書_非通年-子カテ階層の対応.md` 6.5）。

## 使い方

```bash
cd 検証スクリプト

# 1. v53 のコピーで出力マクロを実行し、TXT を生成する
python TXT出力を実行.py v53

# 2. 担当者の本番 TXT と突き合わせる（バイト単位 / 文字単位 / 列単位）
python TXTを比較.py

# 3. 個別の品番や親カテゴリの所在を調べる
python 品番を探す.py GLO-GTP9582
python 品番を探す.py --親カテ "EVER METAL"
```

## ファイル

| ファイル | 内容 |
|---|---|
| `_共通.py` | パス・シート名・列定義。パスは全てこのリポジトリからの相対で解決する |
| `TXT出力を実行.py` | ブックのコピーで `ExportColumnsAEInTXTChunks_ANSI`（Module3）を実行 |
| `TXTを比較.py` | 3段階（バイト / 文字 / 列）で照合し、連結 SHA256 も確認 |
| `品番を探す.py` | 品番・親カテゴリがどの TXT の何行目、どのシートにあるかを表示 |

## 前提

- `pip install pywin32 openpyxl`
- Excel の「VBA プロジェクト オブジェクト モデルへのアクセスを信頼する」が有効
  （`HKCU\Software\Microsoft\Office\16.0\Excel\Security\AccessVBOM` = 1）
- 日本語パスのため、コンソールでは `PYTHONUTF8=1` を付けると安全

## 安全性について

`TXT出力を実行.py` は**本体ブックを開かない。**`_テスト用\` にコピーしてから実行し、
保存せずに閉じるため、本体・git ともに無変更のまま残る。

コピー側では自動実行のため Module3 の `MsgBox` 行だけをコメントアウトする。
出力ロジック（C〜G列 / 2行目から / 500行分割 / ANSI / A列基準の最終行）には手を加えない。

クエリの自動更新は全接続で OFF のため、ブックを開いても「すべて更新」は走らない。
**データを更新したうえで検証したい場合は、Excel で手動で「すべて更新」してから使うこと。**

## 比較の方法

1. **バイト単位** — `"rb"` で読んだ生のバイト列を比較。改行コード（CRLF）・タブ・
   末尾の空白まで含めて差を検出する
2. **文字単位** — cp932（ANSI）でデコードし、`zip()` で1文字ずつ突き合わせる。
   `zip` は短い方で止まるため、長さの一致も併せて見る
3. **列単位** — タブで分割し、C〜G列（ブランド品番 / 変更後セール価格 / 開始日 /
   終了日 / プロパー価格）をそれぞれ列ごとに比較する

最後に全ファイルを連結した単一文字列の SHA256 を照合し、ファイル単位の照合漏れが
無いことを担保する。

バイト数と文字数がずれるのは正常（`【入荷禁止】` のような全角文字が cp932 で2バイトになるため）。
